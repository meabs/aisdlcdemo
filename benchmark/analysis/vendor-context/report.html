When every coding agent reads a different rulebook

The multi-vendor-collision overlay places real vendor file layouts in one tree and makes them disagree on purpose. It measures context tax and exposes where documented precedence ends and guesswork begins.

Do not use this layout in production. The contradictions are benchmark fixtures. A healthy multi-agent repository has one canonical contract and thin vendor references.

Contract recommendation

One source, many pointers. Keep the Agent-Ready Repository Contract in one canonical AGENTS.md and durable docs/contracts. Vendor files should import, @-reference, or plainly point to it rather than restating policy. Keep vendor-only mechanics short and scoped. Never put secrets in local overrides. Avoid competing always-on instructions: every duplicated rule consumes context and creates an undocumented tie-break.

Benchmark connection

The ordinary variants isolate the value of a focused AGENTS.md, OKF knowledge, and the repository contract. The new multi-vendor-collision overlay is intentionally a stress case: it reveals the cost and behavior risk of stacking vendor-specific context. It should be measured separately, never treated as the “fully tuned” optimum.
